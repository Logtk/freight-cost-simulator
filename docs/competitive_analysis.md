# 競合分析: 業界の運賃シミュレーター型サービスと本プロジェクトの位置づけ

本プロジェクトの出発点は、運送業界向けにSaaSを提供するあるベンダーの「運賃シミュレーター型」サービスを業界メディアで知ったことだった。本ドキュメントは、当該サービスの構成を調査した結果と、そこから導かれた本プロジェクトの方針転換を記録する。特定企業の実名・実数値には立ち入らず、**サービス類型としての構造**を分析対象とする。

## 1. 調査で判明した事実(一般化して記載)

このベンダーは、性格の異なる**2種類のサービス**を並行して提供している。

| サービス類型 | 価格帯の傾向 | 中身 |
|---|---|---|
| 運賃シミュレーター型 | 定額サブスク(月数万円規模) | 運行条件を入力し、損益分岐運賃・標準的運賃を即時算出。荷主交渉用の根拠資料も生成 |
| 採算管理型(月次) | 台数比例課金(月数百円/台規模) | コース別・車両別・ドライバー別の**月次**採算(売上/原価/利益率)を可視化 |

シミュレーター型の訴求点は、入力の簡便さ(類似サービスが入力の複雑さで使われなくなる問題への対処)にある。また、運賃値上げ要請を一度断られた事業者が、シミュレーターで作成した資料を用いて再交渉し、実際に運賃改定を実現した事例が業界メディアで紹介されている。

さらに重要なのは、シミュレーター型が同ベンダーの既存の採算分析サービスから**スピンオフして生まれた**という経緯である。つまり同ベンダーにとって本体は採算分析側であり、シミュレーターはその派生・入口にあたる。

## 2. 構造分析: v0.1が作ったのは「入口」だけだった

本プロジェクトのv0.1(単発の原価計算ツール)は、上表の**シミュレーター型だけ**を再現したものだった。これは意図的な選択ではなく、参照した記事がシミュレーター型の紹介記事だったことによる。

この構造上の帰結として、v0.1には「毎月開く理由」が存在しない。

- **シミュレーター型**: 「このコースの原価はいくらか」という問いに答える。この問いは滅多に発生しない(新規コースの引き受け時、運賃交渉の直前など)。よって計算が正確でUIが快適でも、一度使えば用が済む。
- **採算管理型(月次)**: 毎月、先月の実績データが確定する。データが変わるので、見に行く理由が構造的に発生する。

v0.1を評価した際の実感(「経営に刺さらない。現場で一回使ったきりで終わる」)は、精度やUIの不足ではなく、**この構造の違いに起因する**と判断した。したがって改善の方向は、v0.1を磨き込むことではなく、その親にあたる月次採算カルテを新設し、v0.1をその中の1機能として位置づけ直すことになる。

なお、月額課金の観点でも両者は非対称である。台数比例課金は保有台数に比例して伸びる構造で、かつ月次でデータが更新され続ける前提に立っている。定額サブスクより、事業としての継続性は後者にある。

## 3. TTPの対象と、対象にしないもの

本プロジェクトは「徹底的にパクる(TTP)」を方針として掲げるが、パクる対象を明示的に切り分ける。

### パクる: 分析の構造
- コース別・車両別・ドライバー別という**分析の粒度**
- 月次で採算を見るという**時間軸の設計**
- 「どの路線を、いくら、なぜ上げるべきか」という**分析から交渉アクションへの接続**
- 損益分岐運賃と適正原価を並べて提示するという**判断材料の見せ方**

### パクらない: ビジネスモデル
このベンダーの実質的な堀は、月額課金を原資として市況データ(燃料価格、標準的運賃の改定、賃金水準)を継続的に更新し続けることにある。これは運用体制があって初めて成立するもので、本プロジェクト(合成データによるポートフォリオ)では**再現不能かつ再現すべきでない**。

また、価格設定・営業手法・UI意匠の模倣も対象外とする。本プロジェクトが示すべきは分析設計の妥当性であり、製品としての競合ではない。

### 差別化として意識する点
このベンダーのサービスは運送会社(実運送事業者)を主な顧客としている。本プロジェクトは、**発荷主/元請側の視点も同じ計算エンジンで扱える**点を設計上の特徴とする(協力会社への支払いが適正原価を下回っていないかの検証)。この視点はノンアセット型の元請にとって供給継続リスクの管理そのものであり、実運送事業者向けサービスには含まれない論点である。

## 4. 本プロジェクトの位置づけ

以上より、本プロジェクトは**合成データによるポートフォリオ作品**として、以下を示すことを目的とする。

- 運送原価をボトムアップで積算する設計(国交省「適正運賃」の積算要素に準拠)
- その原価を月次の採算管理につなげる分析構造
- 外部環境の変動(燃料高騰等)に対する感度分析とリスクexposureの言語化
- 顧客ポートフォリオとしての採算評価

実データ・実企業名は一切使用しない。詳細は [design.md](design.md) を参照。
